# Grid Sequence Simplification Refactor

### Goals
- Make grid spacing math deterministic and simple.
- Use `last_pending_price` as the single source of truth for NEXT pricing (UI and telemetry).
- Remove `snapshot_next_price` and all dependencies on `next_blueprint_price`.
- In ATR mode: L0 uses ATR(shift=1) anchor; deeper levels use ATR(shift=0) anchor. In Points mode: reuse L0 points distance for all levels.
- Preserve exponential spacing with `Grid_Exponential_Multiplier` (flat when 1.0).

### Key Decisions
- Exponent indexing: when computing the next deeper level after a fill, use `multiplier^(level_index+1)`.
- Fallback policy: if `last_pending_price` is unavailable, compute a minimal blueprint on the fly (no persistent blueprint fields).
- Keep protective-stop math and broker constraints as-is; only simplify distance/anchor math and NEXT propagation.

### Data Model Changes
- Remove from `GridLevelPlan`:
  - `next_blueprint_price` (deleted everywhere).
- Keep `next_resolved_price` only as a volatile fallback holder if needed during planner diagnostics; do not rely on it in UI/telemetry.
- No change to `GridOrderState.last_pending_price` (remains the canonical field for NEXT).

### Algorithms
- ATR_RANGE distances
  - L0 base distance: `abs(entry_side_price - atr_ref(shift=1)) / point_size` (ATR factor already applied inside the indicator via `Grid_ATR_Points_Setup`).
  - For level k>0 after a fill with entry E: `abs(E - atr_ref(shift=0)) / point_size * pow(Grid_Exponential_Multiplier, k)`.
- POINTS_RANGE distances
  - L0 base distance: `Grid_ATR_Points_Setup` (clamped). Anchor derived as now.
  - For level k>0: `base_distance_points * pow(Grid_Exponential_Multiplier, k)` (flat when multiplier=1.0).
- NEXT price
  - `next_price = anchor_for_level + direction_mult * distance_points * point_size`.
  - Persist to `order_state.last_pending_price` when (re)armed or trailed; UI reads this directly.
  - Fallback when `last_pending_price<=0`: compute on-the-fly as above; do not persist.

### New/Updated Helpers
- Indicator anchor resolver (ATR only):
  - `ResolveAtrAnchorPrice(direction, timeframe, shift)` -> price
- Distance calculators:
  - `ComputeBaseDistancePoints(signal_params)` (uses ATR1 or points)
  - `ComputeNextDistancePoints(entry_price, level_index)`
- Minimal fallback:
  - `GridComputeFallbackNextPrice(signal_params, order_state, level_index, point_size)`

### Telemetry & UI
- Logs: replace `next_resolved/next_blueprint` with `next_price` and `next_source=backend|fallback`.
- Keep `LEVEL_NEXT_UPDATE` but emit when `last_pending_price` changes materially.
- UI (`grid_visualization.mqh`): draw NEXT from `last_pending_price`; if invalid, compute fallback via `GridComputeFallbackNextPrice()`.

### Files To Change (high impact)

- `services/trading_signals/grid_planner.mqh` (anchor selection per level; distance math; remove blueprint logging; planner diagnostics)

- `services/frontend/grid_visualization.mqh` (NEXT from backend; remove blueprint branches; fallback helper)

### Phase-by-Phase Delivery
- Phase 2 (Grid Framework)
  - Implement anchor and distance simplifications (ATR1 for L0, ATR0 for deeper; flat points mode).
  - Delete `next_blueprint_price` and plumbing.
  - Add fallback computation; keep planner diagnostics minimal.
- Phase 3 (Order Lifecycle)
  - Make `last_pending_price` the only NEXT source; update TP reference to use backend NEXT.
  - Keep exponential scaling with `multiplier^(level_index+1)` and guard `multiplier>=1.0`.
- Phase 4 (Visualization & Telemetry)
  - Update logs and UI to read backend NEXT or fallback; remove blueprint fields from outputs.
  - Add `next_source` token to logs; validate alignment in Strategy Tester.
- Phase 6 (Docs/Release)
  - Update `README.md` and `AGENTS.md` to reflect the simplified lifecycle and telemetry.

### Acceptance Criteria
- NEXT lines always equal backend `last_pending_price` during runtime; when absent, visibly tagged fallback matches anchor+distance math.
- With `Grid_Exponential_Multiplier=1.0`, NEXT spacing is flat across levels.
- ATR mode: L0 uses ATR1-derived anchor; deeper levels use ATR0-derived anchor; confirmed in `query_debug.txt`.
- No references to `next_blueprint_price` or `GridSnapshotNextLevelPrice` remain.
- Strategy Tester logs show consistent `LEVEL_PENDING`, `LEVEL_NEXT_UPDATE` with `next_source`.
